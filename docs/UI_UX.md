# OpenSink — гайд по UI/UX для дизайнера

## 1. О проекте

OpenSink — кроссплатформенный P2P-мессенджер в стиле Discord без собственного сервера. Внешняя инфраструктура допустима только как публичные STUN, публичные Nostr-реле и WebSocket-трекеры (bootstrap и signaling).

**Платформы:** Linux, Android, Web (Flutter stable, Dart 3).

**Ключевые возможности:**
- Группы, текстовые каналы, голосовые каналы.
- Демонстрация экрана со звуком.
- Голосовые звонки между участниками.
- P2P-передача данных (WebRTC).
- end-to-end шифрование (Ed25519/X25519/XChaCha20-Poly1305), события группы подписаны.

## 2. Ограничения, влияющие на интерфейс

- **Нет центрального сервера** — нет единого источника истины, нет глобального поиска по пользователям вне контактов/групп, нет push-уведомлений через Firebase/Apple (на старте).
- **P2P-звонки** — требуют STUN/TURN-подобного обхода NAT; качество звонка зависит от соединения между peers, UI должен отображать состояние соединения (подключение, RTT, потеря пакетов).
- **Шифрование** — при входе в группу/запуске звока может быть задержка на согласование ключей; UI должен показывать состояние "шифрование настраивается".
- **Локальное хранение** — drift (SQLite) на устройстве; история доступна офлайн.
- **Платформенные отличия:** Web — через браузер (WebRTC, IndexedDB); Android — Keystore; Linux — libsecret/gnome-keyring.

## 3. Целевая аудитория и сценарии

| Роль | Сценарий | Что важно в UI |
|------|----------|----------------|
| Участник группы | Читает текстовой канал, пишет сообщения, заходит в голосовой канал | Чёткая иерархия сервер → категория → канал, быстрый переход между каналами |
| Ведущий звонка | Создаёт голосовой канал, показывает экран со звуком, управляет участниками | Кнопки микрофона/камеры/экрана под рукой, список участников со статусом говорящего |
| Новый пользователь | Генерирует свою Ed25519-идентичность, заходит в группу по invite-ссылке/QR | Простой набор устройства (seed/восстановление), отображение "устройство не подтверждено" |

## 4. Навигация и информационная архитектура

### 4.1. Структура

```
Приложение (окно/вкладка)
├ Боковая панель (серверы/группы)
│   └ Сервер/группа (иконка + имя)
│       └ Категория (опционально)
│           └ Текстовый канал #имя
│           └ Голосовой канал 🔊 имя
├ Основная область
│   ├ Текстовый канал: список сообщений + поле ввода
│   ├ Голосовой канал: панель управления звонком + список участников
│   └ Звонок (полноэкранный/окно): видео/скриншар, элементы управления
└ Профиль/настройки (идентичность, привязки, безопасность)
```

### 4.2. Экраны (минимум для MVP)

1. **Приветствие / создание или вход в устройство** — генерация идентичности, подтверждение seed-фразы (опционально), создание группы.
2. **Список серверов/групп** — боковая панель с иконками и именами групп, статус онлайн/не в сети.
3. **Канал группы** — переключатель категорий, список каналов (текстовые с `#`, голосовые с 🔊), выбранный канал.
4. **Текстовый канал** — лентmessages, аватары авторов, временные метки, статус delivered/read, поле ввода с вложениями.
5. **Голосовой канал** — подключение к каналу, список участников с иконкой микрофона и статусом "говорит", кнопки микрофон/наушники/выход.
6. **Звонок / демонстрация экрана** — крупная область видео/скриншар, плитки участников, элементы управления (микрофон, камера, экран, zakończenie звонка), индикатор качества соединения.
7. **Профиль и безопасность** — отображение публичного ключа/адреса, управление доверенными устройствами, настройки уведомлений.

## 5. Дизайн-система и визуальный стиль

- **Цветовая палитра:** тёмная тема по умолчанию (Discord-подобно), светлая тема как опциональная. Акцентный цвет — фиолетовый/синий._SUCCESS/Warning/Error — стандартные семантические цвета.
- **Типографика:** беззасечные шрифты, иерархия: заголовки каналов, имена авторов, текст сообщения, вспомогательный текст (время, статус).
- **Компоненты:** список каналов, карточка сообщения, аватар с дефолтной иконкой, кнопка иконки (иконка + подпись), переключатель категории, индикатор соединения (точка зелёная/жёлтая/красная), список участников звонка.
- **Анимации:** мягкие переходы между каналами, появление сообщений, индикатор набора текста, включение/выключение микрофона.

## 6. Особые consideration для звонков и скриншеринга

- Элементы управления звонком должны быть доступны в одну касание (микрофон, камера, демонстрация экрана, завершение).
- При демонстрации экрана со звуком — четкий индикатор "транслируется экран + звук" и кнопка остановки трансляции.
- Плитки участников: активный говорящий выделяется (рамка/подсветка).
- Индикатор качества соединения (RTT, потеря пакетов) — небольшая иконка в углу плитки или в строке состояния звонка.
- Режим "только аудио" для голосовых каналов без видео.

## 7. Доступность (a11y)

- Семантические метки для иконок кнопок (минимума: aria-label / Semantics).
- Достаточная контрастность текста (WCAG AA).
- Поддержка масштабирования шрифтов системы.
- Навигация с клавиатуры на Desktop/Web (Tab, Enter, Esc).
- Экраны не должны полагаться только на цвет (статусы соединения и сообщений — иконка + текст).

## 8. Открытые вопросы для уточнения (UI/UX)

- Требования к брендингу: логотип, цветовая палитра, шрифты — ещё не утверждены.
- Нужна ли светлая тема в MVP или только тёмная?
- Макет для мобильных (Android) — отдельная навигация (bottom navigation) или адаптив боковой панели?
- Поддержка тем оформления пользователем (кастомные темы групп)?
- Отображение статуса "вводят сообщение..." в текстовых каналах?
- Максимальное количество плиток участников в grid-завонке (1, 4, 9, 16)?
