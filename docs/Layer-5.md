Слой: core_signaling — Nostr и WebSocket-трекеры.

Задача: две реализации SignalingChannel, работающие параллельно как пул.

NostrSignaling:
- События ephemeral-диапазона (чтобы реле не хранили), тег топика = hash(topic). Проверь по NIP-01: формат события, kind-диапазон, фильтры подписки.
- Nostr требует подпись secp256k1 (BIP-340), а наша identity — Ed25519. Используй одноразовую секп-пару на сессию только для обёртки, а реальная аутентификация внутри payload (Ed25519 + шифрование ключом группы).
- Пул 3–5 реле: параллельная публикация, дедупликация входящих, reconnect с backoff и jitter, health-score, список реле из инвайта + дефолтный конфиг.

TrackerSignaling:
- WebSocket-трекеры в стиле WebTorrent: announce по info_hash=topic, обмен offer/answer. Сверь формат сообщений с актуальной документацией, неясное — TODO(verify).

Общее:
- Presence-анонс (hello) раз в N секунд с capabilities: платформа, public IPv6, uptime, can_relay, can_sfu, список соседей.
- Адресные сообщения offer/answer/ICE; защита от replay (nonce + окно времени); игнорировать всё, что не расшифровалось или подписано не членом группы/держателем инвайта.
- Rate limiting входящего потока.

Тесты: локальный fake-реле (WebSocket-сервер внутри теста), потеря одного реле, дубликаты, replay.
Приёмка: два клиента с общим group_secret находят друг друга через fake-реле и обмениваются SDP; отказ любого одного реле не рвёт обнаружение.
