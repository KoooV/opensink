# MANUAL QA — SecureKeyStore на Android

Выполняется на физическом устройстве или эмуляторе с Google Play Services (Keystore).
Если эмулятор в CI недоступен — тестирование вручную перед релизом.

## Чек-лист

### 1. Первичная установка и запуск
- [ ] Приложение устанавливается и запускается без падения.
- [ ] При первом запуске `secureKeyStoreProvider` получает реальную реализацию (не `StateError`).
- [ ] Создание новой идентичности → `storeIdentity` возвращает `Ok`.
- [ ] Повторный запуск приложения → `loadIdentity` возвращает сохранённую идентичность.

### 2. Перезапуск приложения
- [ ] Полная остановка приложения ( swipe away / Force Stop ) → повторный запуск → `loadIdentity` возвращает ту же идентичность.
- [ ] Данные сохраняются между перезапусками процесса.

### 3. Перезагрузка устройства
- [ ] После перезагрузки устройства → запуск приложения → `loadIdentity` возвращает идентичность (Keystore сохраняет ключи после перезагрузки).
- [ ] Экран блокировки разблокирован перед запуском (Keystore требует разблокированного экрана для доступа к ключам).

### 4. Резервное копирование и восстановление
- [ ] Включить Google Auto Backup (adb: `adb shell bmgr fullbackup <package>`) → данные приложения бэкапятся в Google Drive.
- [ ] Удалить приложение → установить заново → выполнить восстановление из бэкапа.
- [ ] При восстановлении на новом устройстве с недействительным ключом Keystore → `loadIdentity` возвращает `Err(StoreCorrupted)` или `Err(StoreUnavailable)` без падения приложения.
- [ ] Приложение не падает при несовместимой версии схемы stored данных → `StoreCorrupted`.

### 5. Смена экрана блокировки
- [ ] Установить/изменить PIN/паттерн/пароль экрана блокировки.
- [ ] Запуск приложения после смены блокировки → `loadIdentity` работает (Keystore ключи привязаны к экрану блокировки, доступ сохраняется).
- [ ] Удаление экрана блокировки (безопасность → нет блокировки) → Keystore может invalidate ключи; приложение обрабатывает ошибку без падения.

### 6. Ошибки хранилища
- [ ] Keystore недоступен (устройство без支持 Keystore, редкий случай) → `storeIdentity`/`loadIdentity` возвращают `Err(StoreUnavailable)` без падения.
- [ ] Повреждённые данные в хранилище (вручную изменить SharedPreferences/файл) → `loadIdentity` возвращает `Err(StoreCorrupted)`.
- [ ] Никакого тихого отката на файл в открытом виде при любой ошибке.

### 7. StrongBox
- [ ] StrongBox **не обещан** — приложение работает и без StrongBox (отсутствие StrongBox не является ошибкой).

### 8. Безопасность
- [ ] Дамп файлов данных приложения (`adb backup` или root) не раскрывает `privateSeed` в aberto (шифруется Keystore).
- [ ] `toString()` идентичности и бандла не раскрывает `privateSeed` в логах.

## Примечания

- flutter_secure_storage v9.2.4: файлы хранилища исключены из Auto Backup через `android:allowBackup` и `android:fullBackupContent` в `AndroidManifest.xml` (TODO(verify): точные настройки для v9.2.4).
- Keystore ключи привязаны к экрану блокировки устройства. При смене экрана блокировки ключи могут стать недоступны — приложение должно обрабатывать `StoreUnavailable`/`StoreAccessDenied`.
