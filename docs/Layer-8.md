Слой: core_group.

Задача:
1. Административные события: group_create, invite_issue, member_join, member_remove, role_set, channel_create/delete, key_rotate.
2. GroupState.apply(event) — детерминированная чистая функция; права проверяются по состоянию в причинной позиции события.
3. Роли: owner, admin, moderator, member; права на каналы.
4. Правила конфликтов (задокументируй явно и покрой тестами): owner неприкосновенен; конкурентные действия равных ролей — по (hlc, затем меньший event id); взаимные кики; кик против смены роли.
5. Инвайт-ссылка: gid, group_secret, pubkey админа, hint по реле. Предусмотри режимы: открытая ссылка (с лимитом использований/сроком) и вход с подтверждением админом. Подумай, как утечка ссылки влияет на безопасность, и отрази в design doc.
6. Ротация sender keys при удалении участника; раздача новых ключей по E2E-зашифрованным личным сообщениям.

Тесты: сценарные тесты конфликтов; property-тест «результат не зависит от порядка применения».
Приёмка: любой порядок доставки одного множества событий даёт идентичный GroupState.
