# Дизайн: подпись на уровне Envelope и SyncEvent

## Статус
Черновик. `core_protocol` уже реализует подпись/проверку `Envelope`; `core_sync`
подписывает собственные события; `core_group` и `core_media` ещё не реализованы,
поэтому сквозной поток group/media ниже остаётся проектным решением.

## Контекст
Принцип проекта: любое событие, влияющее на состояние группы, подписано Ed25519 и
валидируется до применения. Нужно однозначно ответить:

- подписывается ли доменное событие отдельно от конверта;
- кто верифицирует подпись;
- как в модель вписываются медиа-события, которые не меняют состояние группы.

## Текущее состояние кода

| Компонент | Фактическое поведение |
|-----------|-----------------------|
| `core_protocol` | `Envelope.signatureData()` покрывает поля 1–4 и `payload`; `ProtocolCodec.sign/verify` работают с Ed25519. `unknownFields` не входят в зону подписи. |
| `core_sync` | Подписывает не `Envelope`, а `SyncEvent`: `event.id = SHA-256(domain || canonical)`, подпись — над `domain || canonical`. Конвейер пересчитывает id и проверяет подпись до записи. |
| `core_group` | Заглушка; `GroupEvent.validateInvariants()` существует в `core_domain`, но `Group.apply` и права не реализованы. |
| `core_media` | Заглушка; медиа-события и `MediaTopology` не реализованы. |

## Решение для group/media

Для будущих групповых и медиа-сообщений используется единый `Envelope`:

1. Домен создаёт событие (`GroupEvent` или медиа-сообщение).
2. Событие сериализуется в `payload`.
3. Собирается `Envelope{version, type, sender, hlc, payload, signature}`.
4. `signature = Ed25519.sign(envelope.signatureData(), privateKey)`.
5. Получатель сначала проверяет подпись конверта, затем декодирует `payload` и
   валидирует инварианты домена.
6. `core_sync`/`core_group` применяют событие только после успешной проверки.

Для `SyncEvent` сохраняется отдельная подпись над каноническим телом, потому что
это транспортно-независимый элемент лога. Если `SyncEvent` пересылается внутри
`Envelope`, проверяются обе подписи: конверта и события.

### Зона подписи `Envelope`

- Входят: поля 1–4 (`version`, `type`, `sender`, `hlc`) и `payload`.
- Не входят: `signature` (циклическая зависимость) и `unknownFields`
  (маршрутные метаданные реле).
- `sender` — Ed25519 public key отправителя. Соответствие `sender` известной
  личности/`PeerId` проверяется слоем синхронизации или членства.

## Границы ответственности

| Слой | Отвечает за |
|------|-------------|
| `core_domain` | Модели событий, инварианты, чистые проекции. Не знает о подписях. |
| `core_protocol` | `Envelope`, `signatureData()`, сериализация, `sign/verify`. |
| `core_crypto` | `Signer`, Ed25519, `SecureKeyStore`. |
| `core_sync` | Приём `SyncEvent`, проверка id/подписи, membership, запись. Проверка подписи `Envelope` будет добавлена при упаковке group/media-сообщений. |
| `core_group` | Права, роли, `Group.apply`, валидация групповых событий. |
| `core_media` | Медиа-конверты, топологии, звонки. |
| `platform_*` | Реализация `Signer` и защищённого хранения ключей. |

## Что не делается

- Отдельная подпись каждого поля `GroupEvent` — избыточна.
- Подпись медиапотоков SRTP/SRTCP на уровне приложения — WebRTC шифрует транспорт.
- Доверие к `unknownFields` — они не аутентифицированы и не влияют на доставку.

## Риски

- Реле может менять `unknownFields` без инвалидации подписи. Допустимо только если
  эти поля не используются для решений о доставке.
- Подмена `sender` возможна только вместе с переподписью; защита — сверка `sender`
  с известной личностью или членством группы.
- `core_sync` и `Envelope` используют разные домены подписи; при упаковке
  `SyncEvent` в `Envelope` нельзя пропускать ни одну из проверок.

## Открытые вопросы

1. Схема protobuf для `GroupEvent` в `payload` — реализована в `core_protocol`, но
   не подключена к `core_group`.
2. Сопоставление `Envelope.sender` с `GroupEvent.authorId` — правило должен
   определить `core_group`.
3. Нужно ли поле `groupId` в заголовке `Envelope` для фильтрации без декодирования
   `payload`.
4. Пишутся ли медиа-конверты в `EventStore` или остаются только в транспорте.

## Критерии приёмки

- `core_group` не вызывает `Signer.sign/verify` напрямую.
- `core_media` не создаёт `GroupEvent` и не вызывает `Group.apply`.
- Все входящие `Envelope` проверяются на подпись до семантического разбора.
- `GroupEvent.validateInvariants()` вызывается после проверки подписи и до
  применения.
- Тесты: неверная подпись конверта отклоняется; событие с нарушенными инвариантами
  не применяется.
