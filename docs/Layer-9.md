Слой: core_relay.

Задача: прозрачная пересылка данных через общего соседа, когда прямое соединение не установилось.
1. Знание топологии: из presence-анонсов (списки соседей) строится граф достижимости.
2. Transport.send(dst, bytes): сначала прямой линк; если ICE не уложился в таймаут — путь через пира, имеющего линки с обоими. Максимум 2 хопа, TTL, кэш виденных фреймов против петель.
3. Сквозное шифрование: релей видит только заголовок RelayFrame.
4. Opt-in: пользователь включает «работать ретранслятором»; на Android по умолчанию выключено при мобильном трафике и низком заряде. Лимиты полосы на источник, метрики.
5. Добровольные постоянные узлы (public IPv6 / доступный порт) объявляют can_relay и ёмкость; выбор релея по нагрузке и RTT.
6. Failover: пропал релей — пересчёт пути без потери сообщений (доставка через sync всё равно догонит).
7. Описи в design doc: как релеить медиа (аудио-трек пересылается через топологию слоя 13, а не через RelayFrame).

Тесты: симуляция A–C–B, где A и B не видят друг друга; потеря C; петли; злоупотребление лимитами.
Приёмка: сообщение A→B доходит через C, C не может его прочитать; при исчезновении C A и B перестраивают путь или ждут sync.
